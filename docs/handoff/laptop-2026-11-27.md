# Laptop handoff: narration v2 and the montage hook, 2026-11-27

Paste this into a Claude Code session on the laptop. The laptop renders; the narration page runs on the PC.

## Where we are

- Branch `feat/clip-edits` (built on `feat/narration-v2`; not merged to master, the owner merges). It carries the narration timeline work and the hook clip edits (join map v2, `story-join --apply-edits`). `feat/narration-v2` adds the narration timeline (takes in pieces, record-over, trim/split/nudge/mute/gain, game-audio regions, duck) and `story-join --hook-mode play`. Reference: `api/docs/narration.md`, spec `docs/specs/spec-narration-v2.md`.
- Standing rules: never read `api/.env`; opponents by champion only; narration takes and mic audio stay on the PC and never go to Drive or Supabase.

## Do this

1. `git fetch && git checkout feat/clip-edits` (do not merge to master).
2. `cd api && uv sync`; `cd ../web && bun install`.
3. Run the tests: from `api/` `uv run pytest -q`; from `web/` `bun run test` and `./node_modules/.bin/tsc -b`.
4. Re-join the video with the montage hook. The three round names are the `games[].round` fields of `WORKSPACE/story/joined_2026-11-26_xayah-kaisa-yunara.join.json`, in game order (Xayah, Kai'sa, Yunara):
   `uv run story-join <xayah round> <kaisa round> <yunara round> --hook 3:2 --hook 2:2 --hook 1:2 --hook 3:5 --hook-mode play --hook-title "Want to know the trick to laning?" --outro`
   Picks (game:chapter): Yunara 2v3, Kai'sa 4v4 top, Xayah 2v2, Yunara 3v2 objective fight at Horde (the dive setup, 8:01). Heavy renders one at a time.
5. Check the output: hook plays through each outcome (no freeze, no card), `.join.json` and `.chapters.txt` rewritten next to it.

6. Apply the owner's hook edits. The step 4 join, run on `feat/clip-edits`, writes the v2 map (with a `hook` block) that the PC page needs for the hook lane; maps joined on older branches show markers only. After the owner edits the hook on the PC, pull `WORKSPACE/story/<stem>.edits.json` from the PC by hand, then run `uv run story-join --apply-edits <stem>` with no other flags (MCP `story_join(apply_edits="<stem>")`; `--out`, `--title`, `--hook*`, `--outro`, `--music*` and `--subscribe-after` are refused with it). It refuses when the map changed since the edits (`--force-edits` overrides), writes one managed extend per chapter whose clip runs past its footage and re-renders each touched round once (with `--plays` when the story was cut from plays), re-joins with the picks, mode and title from the edits file and the options (subscribe, outro, music start, title) from the map, and deletes the edits file. Send the new mp4, `.join.json` and `.chapters.txt` back to the PC the same way as before.

## Drive
